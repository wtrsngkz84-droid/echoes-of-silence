## 0. 总体路线

产品分七个阶段推进，**每阶段独立交付、独立审阅**，避免一次性产出未经检查的大量剧情：

| 阶段 | 内容 | 对应职责（工作指令） | 状态 |
| --- | --- | --- | --- |
| P0 基础与范围 | 任务清单 + PRD | 职责一 | 待审阅 |
| P1 故事圣经 | 客观时间线、知情矩阵、人物小传与关系、创作红线 | 职责二、三 | 待审阅 |
| P2 流程与规则 | 章节流程、分支、状态变量、结局判定条件 | 职责五、七 + 职责六的规则层 | 初稿完成（待审阅；按用户指示提前启动，先于 P1 审阅） |
| P3 剧本 | 三章逐节点场景、台词、选项与后果（逐章交付、逐章自检） | 职责四、五 | 未开始 |
| P4 资源需求 | 像素人物、背景、UI、音效规格与授权 | 职责八 | 未开始 |
| P5 验收标准 | 可执行的验收场景与预期结果 | 职责九 | 未开始 |
| P6 开发交接 | DEV_HANDOFF 交接包 | 职责十 | 未开始 |

**关键审阅门**：P1 故事圣经是全部剧情的地基（事件事实、人物动机、跨视角信息差都在此定稿）。P3 剧本必须在 P1 获产品负责人确认后才开始批量撰写。
